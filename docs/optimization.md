# 性能优化记录（2026-11-10）

方法：先建微基准定位热点，再逐项改、逐项验。每项优化都要过三关——数值等价或精度对照实验、完整测试套件、仿真表回归。本机是 1.5 核共享 CPU（有节流），绝对数值仅供参考，结论以同进程交替 A/B 的相对值为准；目标硬件（NUC）上多核项的收益会更大。

## 基线（优化前）

| 环节 | 耗时 |
|---|---|
| Detector::detect（1440×1080，2 装甲） | ≈ 6.5 ms/帧 |
| PoseSolver::solve（开 yaw 优化） | ≈ 1302 µs/块 |
| Ballistics::solve | ≈ 45 µs/次（上一轮已优化） |
| Tracker + Aimer | ≈ 111 µs/帧 |

## 采纳的优化

### 1. 投影去 projectPoints 化（pose.cpp）——最大头
`CameraModel::project` 原来对每个点调用一次 `cv::projectPoints`（带 vector/Mat 分配与通用畸变路径），而 yaw 扫描每块装甲要调约 800 次。改为直接实现针孔 + (k1,k2,p1,p2,k3) 畸变公式（OpenCV 5 系数模型同式），内参/畸变在构造时缓存；超过 5 个畸变系数的模型仍回退 projectPoints。
- 等价验证：随机 10048 个点与 projectPoints 对照，最大偏差 4.2e-12 px。
- 效果：**solve 1302 µs → ≈72 µs（约 18×）**，解算结果 yaw 一致到小数点后 4 位。

### 2. yaw 扫描由细到粗改粗到细（pose.cpp）
原：LOS ±85° 以 1° 步进全扫（171 次重投影）+ ±1° 黄金分割 20 次。改：2° 网格（86 次）+ 获胜点 ±2° 黄金分割 16 次（终精度约 0.002°）。
- 精度验证：300 个随机位姿（2–9 m、yaw ±69°、0.3 px 噪声）新旧对照——yaw 误差均值 13.81° vs 13.84°、中位同为 11.05°，位置误差四位小数一致，重投影误差新版略低。统计等价。
- 效果：扫描段约省 10–15 µs/块（快速投影落地后 PnP 本身占约一半，扫描收益相对变小）。

### 3. solveAll 并行（pose.cpp）
每块装甲的 solve 互相独立（const、无状态），用 `cv::parallel_for_` 并行，结果保持输入顺序、失败剔除语义不变。本机受共享 CPU 限制测不出并行收益（288 µs vs 288 µs），真实多核上才有意义；无实测负面影响。

### 4. 检测二值化融合单遍（detector.cpp）
原链：split（三通道全帧拷贝）→ subtract → threshold，共 3 遍全帧 + 2 张全帧中间图。改为单遍融合循环（parallel_for_ 按行）：`mask = sat(R−B) > thr ? 255 : 0`，与旧链**逐像素一致**（随机场景 1866 万像素对照 0 差异）。自适应阈值开时仍走旧链（需要 diff 图做统计），非 8UC3 输入走旧链兜底。
- 效果：同进程交替 A/B 三轮，detect 6218/6919/7508 µs → 5430/5887/6088 µs，**约 −15%（≈1 ms/帧）**。

## 试过但否决的（附证据）

- **形态学 CLOSE 迭代 2→1**：闭运算理论上幂等，但 OpenCV 实现下随机掩膜对照有 0.044% 像素不同（边界处理），可能影响贴边灯条的轮廓，无实拍回归素材可兜底，否决。
- **split 改 extractChannel×2**：实测更慢（2.40 ms vs 1.45 ms），split 的单遍解交织反而最快，否决。
- **分类器多装甲批处理 DNN forward**：实测分类仅占约 0.3 ms（2 块装甲），收益太小、改动风险不成比例，暂缓。

## 后续可做（未做，说明原因）
- **跟踪引导 ROI 检测**（开源常见做法，如 sp_vision 的跟踪窗）：已跟踪时只在预测窗内做二值化/轮廓，可再省数 ms。但它改变检测器的状态模型，需要实拍视频验证丢跟恢复逻辑，本轮无素材，不盲改。接口上 detect() 目前无状态，落地时建议新增带 ROI 的重载而非改默认行为。
- **PnP 本身**（约 35 µs/块）：IPPE 已是解析法，进一步只能换更 cheap 的初始化+单次迭代精化，精度风险大于收益。

# ADR-001：单一共享核心（core/），步兵/英雄/哨兵共用一份实现

- 状态：已接受（2026-11-10 合并时落地）
- 背景：合并前有 rm-autoaim（步兵）与 rm-sentry-integration（哨兵）两条
  代码线，各自一份检测/PnP/跟踪/弹道，修复要改两遍且已经出现行为漂移
  （例如哨兵侧俯仰符号约定与主仓相反、弹速字段缺失）。
- 决策：单仓单核心。core/ 存唯一一份算法实现（autoaim_core），哨兵差异
  （多目标管理、串口、前哨站、ROI）全部放 sentry/ 模块（autoaim_sentry，
  只依赖 core），应用层在 apps/ 与 sentry/apps/ 组合。
- 后果：核心修复一次生效于所有机器人；代价是核心 API 变更必须同时考虑
  哨兵调用点，CMake 目标依赖方向（sentry → core，永不反向）成为硬约束。
- 备选与否决：保持两仓 + 子模块同步——漂移已经发生，否决；把哨兵逻辑
  并入核心大类——不同机器人的业务差异会污染共享实现，否决。
- 证据：docs/project/monorepo_migration.md（合并逐文件决策与回归证据）。

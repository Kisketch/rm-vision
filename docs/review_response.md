## 二、评审说错的地方

1. **`yaw_gain = 1.0`** —— 错。`config/default.yaml` 里是 **1.3**，评审读的是头文件默认值。这个值来自“同帧两块板必须相差 90°”的自校准（实测 69.3°/69.7°），是整套 yaw 估计的基础。
2. **“自适应过程噪声”是亮点** —— 错。`q_scale = clamp(NIS_ema/3, 1, q_adapt_max)`，而位置 NIS 稳定在 3 附近，所以 `q_scale` 恒等于 1，**从未生效**。README 早已写明，评审把“代码里有”当成了“起作用”。
3. **“13 维整车模型”** —— 名义上是 13 维数组，但 `ca_model=0` 时加速度两维不参与预测，**有效仍是 11 维**；CA 我们也试过并被真实视频否决（−5~−7 pp），因为 25 fps 下加速度不可观测。
4. **Tier-2 建议“用 sigma_lat 自适应开火窗口”** —— 前提不成立。协方差是为响应速度调的，不是标定过的不确定度；`fire_sigma_scale` 默认 0（关闭），因为一开就几乎不开火。

## 三、评审说对但我们已经知道的

- 提帧率、YOLO 关键点、云台 yaw-rate 前馈：与我们 `docs/BACKLOG.md` 的 B-01/B-02 完全一致，缺的都是外部条件（GPU、数据集账号、电控配合），不是算法认知。
- 8 帧断档 ≈ 320 ms、miss 分析数字：与我们 `docs/miss_analysis.md` 一致。

## 四、评审没想到、我们采纳的思路

**双板同帧 90° 约束**：方向是对的，但直接加“伪观测”与现有模型重复——EKF 的观测模型本来就写了 `armorYaw(x,k)=yaw+k·π/2`。真正的缺口是**相关误差**（辉光让两块板的 yaw 同向压缩），要治得加公共偏置状态或改用角平分线观测。评估后暂缓，记录在 `docs/BACKLOG.md` B-04。

## 五、本轮净结果

| 指标 | 评审前 | 评审后 |

| 3.avi 命中率 / 射频 | 67.2% / 10.2 | **67.6% / 10.6** |
| 4.avi 命中率 / 射频 | 68.1% / 9.5 | **68.6% / 10.0** |

# RM-PRO execution record — 2026-11-04

Scope: improve the existing `autoaim` system while preserving the delivered
`rm-armor-detection` assessment repository, its 3.txt/4.txt outputs, source
data, and prior reports. This branch is `feat/camera-calibration`.

## Completed in this pass

- Added `tools/calibrate_camera.py`: chessboard intrinsic/distortion calibration
  with per-view RMS, coverage diagnostics, and a camera YAML for the pipeline.
- Added `autoaim_video --camera`: loads measured intrinsics/distortion separately
  from the tuned detector/tracker settings and rejects image-size mismatch.
- Added optional calibration image width/height fields to `CameraConfig`; old
  configs continue to load unchanged.
- `autoaim_video` now uses recording FPS metadata for replay time and retimes
  existing cached detections; frame-count mismatches invalidate the cache.

The tool was exercised on 18 generated 1280x960 checkerboard views: 18/18
detected, RMS 0.124 px, max per-view RMS 0.278 px; recovered fx/fy 1027.74/
1048.28 px versus generating 1000/1020 px. The generated video passed through
`--camera`; a 1440x1080 input with that calibration was rejected as expected.
`autoaim_tests` passed. These are synthetic tests, not physical calibration.

## Investigated and withheld

We tested a lateral acceleration predictor on the simulator and cached real
videos. Unrestricted gain 1 improved hard-strafe virtual hit rates from 43.1%
to 59.5% and 18.2% to 26.2%, but reduced real-video rates from 62.5% to 55.1%
and 59.6% to 48.3%. A 0.8 m/s speed gate restored real-video results but also
removed the hard-strafe gain. The experiment was reverted from source. Raw
outputs are retained under `/home/lgnatius/RM/autoaim-experiments/`.

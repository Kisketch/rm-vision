# 待办池（用户确认"后期再做"的两项）

> 建立于 2026-11-05。这里只记录**已定方案、已量化收益、缺外部条件**的事项；
> 视觉侧自己就能做的改动不放这里（直接进分支）。

## B-01 云台速度前馈（需要电控配合）

| 项 | 内容 |
| --- | --- |
| 现状 | 视觉每帧下发 yaw/pitch 角度；云台按一阶滞后跟随（τ≈30 ms，限速 12 rad/s） |
| 仿真证据 | `gimbal_ff` 从 0 → 1.0：硬平移场景 43.8% → **51.1%**，整体均值 78.0% → 79.2%；ff=0.5 时无旋转硬平移 14.4% → 18.0% |
| 需要 | 电控在接收角度的同时接收 **yaw rate**（或云台控制器内部做速度前馈）；视觉侧愿意按固定频率发 `yaw, yaw_rate, pitch, pitch_rate` |
| 验收 | 仿真 `gimbal_ff=1` 的收益在实车复现 ≥ 5 pp（硬平移场景），且不影响稳态精度 |
| 备注 | 这是评测参数，默认 0；不改默认值就不会污染交付数字。视觉侧已补齐：`AimCommand` 现带 `yaw_rate`/`pitch_rate`（差分+钳制，见 `docs/gimbal_ff.md`），剩余阻塞只有电控消费与实车验收 |

## B-03 IMM（交互多模型）

- 目前不做。CA（常加速）已在 25 fps 数据上验证失败（真实视频 −5~−7 pp），说明**加速度不可观测**是瓶颈，换 IMM 不会改变这一点。
- 触发条件：相机换到 ≥100 fps，或引入 IMU/轮式里程计提供自身运动补偿后再评估。

## B-04 双板同帧 90 度约束（评估后暂缓）

- 来源：外部评审建议。想法是同一帧看到两块板时，用"它们必须相差 90°"作为伪观测来压低 yaw 的公共偏差。
- 现状：整车 EKF 已经把 `armorYaw(x,k) = yaw + k*pi/2` 写进观测模型，两块板依次融合时本身就带了这个约束，所以"再加一条 90° 约束"与现有信息重复。
- 真正的缺口是**相关误差**：辉光导致的 yaw 压缩对两块板是同向的（`yaw_gain` 就是在补这个），要治它需要给滤波器加一个公共偏置状态，或只用两块板的角平分线做观测——属于滤波器改造，不是一行约束。
- 暂缓理由：改造成本约 1-2 天，收益不确定；先把 `q_yaw` / `q_r` 的平台区用尽（本轮 +0.4/+0.5 pp）。触发条件：双板同帧帧数占比提升（如补拍侧向数据），或 yaw 偏差被证明是主要误差项。

## B-05 参数空间已扫尽（2026-11-05）

- 在滞回修复、`q_yaw=3`、`q_r=3e-3` 的基础上，又扫了 5 个此前未动或未复扫的旋钮：
  `singer_tau`、`q_dz`、`pixel_noise`、`r_yaw_head_on`、`max_match_distance`。
- 结论：没有一个能在两条视频上同时超过现值（详见 README 的 "The remaining knobs are flat"）。
  `max_match_distance=0.25` 能把命中率抬到 68.1/70.8，但射频掉 1.1–1.2 发/s，DPS 反而更低，否决。
- 因此"继续调参"这条线到此为止；再往上只能改信息条件（B-01 前馈、B-02 关键点、更高帧率）。
- 回归门禁：`python3 tools/regression.py`（对比 BASELINE §10，退化即非零退出）。

# 丢失期速度延续（carry_velocity）

## 背景

D-01：重捕后 ≤3 帧命中 62.2%，稳态 68.1%。warmup 门证明“少开火”是负收益，于是换方向：
**让重捕第一帧就准**，而不是躲开它。

旧行为：`LOST` 后 `init()` 把状态清零重来，`vx=vy=ω=0`——等于认为目标停了下来，
前几帧全靠滤波器重新收敛。

## 改动

`tracker.carry_velocity`（默认开）：重新初始化时，若距上次更新 <1.5 s，
把 `vx / vy / ω` 从旧状态继承过来，位置仍用新观测，协方差保持宽（p0 本来就给 1.0 m/s、3.0 rad/s）。

## 实测

| carry | 3.avi | 4.avi |
|---|---|---|
| 关 | 67.6% / 10.6 | 68.6% / 10.0 |
| **开（默认）** | 67.6% / 10.6 | **68.7% / 10.1** |

3 号完全不变，4 号 +0.1 pp、+0.1 发/秒。**收益接近噪声**。

## 为什么没效果

重捕大多发生在**短丢失**（TEMP_LOST，<0.4 s）之后，这条路径本来就不走 `init()`；
真正走 `init()` 的 LOST 只有 8 帧断档那种长丢失，而那时速度早已变了，继承旧值帮助有限。

## 结论

- 保留默认开启：原理正确、零代价、4 号微正。
- 但它不是那 18.4% 重捕射击的主因。**重捕差是因为观测少（一两帧），不是因为没有先验**。
- 要真正改善，得让 `tracking_thres=3` 期间就有可用的估计——例如用**单帧 + 运动学约束**直接解出
  初速度（两帧差分），或者把 `tracking_thres` 降到 2 并用更大的初始协方差兜住。
  这已经是滤波器结构问题，不是加一个开关能解决的。

*数据来自两视频虚拟射击，回归门禁 PASS（4 号 +0.1）。*

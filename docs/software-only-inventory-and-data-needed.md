## 明确不做的（已有数据否决）
- 继续调参：B-05 已扫尽 5 个剩余旋钮，两条视频上无一能同时超过现值；`max_match_distance=0.25` 能抬命中率但射频掉 1.1–1.2 发/s、DPS 反而更低，已否决。
- 常加速 CA / IMM：CA 在 25 fps 真实视频上掉 5–7 pp，加速度不可观测；触发条件是相机 ≥100 fps 或引入 IMU/里程计自身运动补偿。
- 双板 90° 公共偏置：整车 EKF 观测模型已隐含该约束，信息重复；触发条件是双板同帧占比上升或 yaw 偏差被证明是主要误差项。
- 能量机关（打符）：独立第二任务链，队伍明确分配后再另起模块。

3. **实测弹速**：17 mm 裁判系统/枪口测速值（随温度、电压、摩擦轮状态的漂移）；42 mm 的 `bullet_speed_42` 默认 16 m/s 是占位、`drag_k_42` ≈0.009 是按公式推导，都须英雄实车拟合/实测。哨兵要喂实测弹速须先定协议（字节 2 或扩帧）。
4. **MVS 相机信息**：相机型号、MVS SDK 版本、曝光时间、硬件触发（Line0）对应关系、像素格式、MCU 姿态发送频率。MVS 分支按 4.x API 写，在本机未编译验证，须在装 SDK 的机器上首次编译核对。
5. **电控确认（两项）**：① yaw rate 正式接收字段（替代塞进 `ui_x` 的临时做法）；② 协议 CRC/校验和 + MCU 时间戳字段 + 唯一 DeviceId 是否进协议、何时进。
6. **YOLO 自训才需要（现在不启动）**：GPU 机器（约 13 GPU·h；本机 CPU 约 770 CPU·h 不可行）、Roboflow 账号/API key（ARUW 18,557 张、Sam 23,282 张）。先用深大开源 V8 模型验证路线是否够用，再谈自训。
7. **协议/时间戳的根本限制（须知）**：下位机 17 字节帧不带时间戳，姿态戳只能用接收时刻减估计延迟；G-02 的 0.3 ms 对齐预算在这条链路上是估计不是保证，真实抖动须上车测；17 字节 ×10 bit ÷115200 波特 ≈1.48 ms 传输时间本身已超 0.75 ms 预算量级，须靠实测延迟补偿。

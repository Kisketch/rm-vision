# 跟踪引导的窗口（ROI）检测

## 接口

`Detector::detect(bgr, windows, debug)`：只在给定的全帧坐标窗口内做灯条搜索，之后的配对、角点精化、数字分类与全帧检测完全共用同一条路径（`finishDetect`）。语义：

- `windows` 为空 == 全帧检测（逐像素一致）；
- 窗口外的装甲不会被检出（这是定义，不是缺陷）；
- 窗口边缘切到的灯条会变短甚至被过滤掉，所以窗口必须在预测位置外留边距（实验用 110 px）；
- 重叠窗口检出的同一灯条按中心距 < 2 px 去重；
- ONNX 关键点后端下窗口模式回退全帧检测。

## 推荐用法（哨兵仓已接线，`sentry_robot --roi`）

窗口来源（2026-11-10 起改为跟踪器预测，见文末真实视频验证）：每帧检测前，由 TargetManager 中每个活跃跟踪的**整车预测状态**生成窗口——目标全部装甲位在当前时刻的预测位置（armorAt）以当前帧云台姿态投影、取角点包围盒 + 60 px 边距；每 30 帧强制一次全帧扫描；窗口帧检出为空时**同一帧立即全帧重扫**（丢跟恢复不延迟到下一帧）。主仓的离线评测程序是两段式（先全量检测再评估），没有实时环路可接，窗口模式以库接口 + 单元测试 + 序列实验的形式交付。

## 验证（合成序列实验，2026-11-10）

渲染 360 帧 1440×1080 合成序列：目标以 2.5 rad/s 自旋、中心做 Lissajous 平移（约 5 m），带背景杂物与传感器噪声。两条流水线（检测→PnP→EKF→瞄准）对照：

| 指标 | 全帧检测 | 窗口检测 |
|---|---|---|
| 跟踪帧数（/360） | 359 | **360** |
| 有检出的帧数 | 359 | 359 |
| 检测耗时 | 20.8 ms/帧 | **6.4 ms/帧（约 3.3×）** |
| 瞄准 yaw 差异（355 帧双方有效） | — | RMS 0.0135° |

窗口模式跟踪帧数不少于全帧（窗口外杂物灯条被排除，偶尔还少一次误检干扰），瞄准指令差异在百分之一度量级。单元测试覆盖：窗口内复现全帧结果（中心 < 1.5 px）、窗口外目标剔除、空窗口等价、重叠窗口去重。

注意：以上是合成序列结论；真实相机流上的丢跟恢复表现仍需上车/实拍验证，因此哨兵接线默认关闭（`--roi` 显式开启）。

## 真实视频验证与窗口策略定型（2026-11-10）

在两段真实回归视频（2,209 + 3,416 帧，1440×1080）上端到端对照三种窗口
策略（窗口检测结果再喂回仓库评测，全帧检测为参照与基准）：

| 策略 | 慢旋视频漏检 | 快旋视频漏检 | 检测均耗时 | 端到端命中率 |
|---|---|---|---|---|
| 全帧（基准） | 0 / 2380 | 0 / 3885 | ≈6.5–7 ms | 67.5% / 68.6% |
| 上一帧观测窗口 +110 px（旧） | 49 | 14 | 1.37 / 1.24 ms | 67.3% / 68.4% |
| **跟踪预测窗口 +60 px（现行）** | **3** | 15 | 1.62 / 1.34 ms | **67.8% / 68.3%** |
| 跟踪预测窗口 +110 px | 48 | 98 | 2.27 / 2.13 ms | 67.5% / 67.9% |

结论：
- 预测窗口的价值在装甲交替出现的时刻：慢旋视频漏检 49 → 3，端到端命中率
  与全帧持平（差异在噪声内）；快旋视频与旧策略打平。
- 边距不是越大越好：110 px 时窗口大面积重叠，灯条在窗口边界被截断产生
  重复/伪装甲并回灌跟踪器，漏检反而暴涨（快旋 98）。60 px 是实测甜点。
- 哨兵接线集成复验：4.avi 前 800 帧，`--roi` 开/关两路 SentryVision 的
  逐帧观测数完全一致（890 = 890，0 帧不同）。
- `--roi` 仍默认关闭：以上是固定相机素材，云台运动下的预测投影精度需
  上车验证；开启方式不变（`sentry_robot --roi`）。

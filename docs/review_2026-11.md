# 代码审查、复刻与优化（2026-11）

分支 `optimize/core-hardening`。本文记录：完整性检查结论、复刻方式、发现的缺陷
（按严重度）、已实施的优化及其数据、以及合并前必须在实拍/实车上补做的验证。

## 1. 复刻方式与边界

审查环境没有 OpenCV C++ 库且无法联网安装，因此用一个最小的 OpenCV 兼容层
（`Matx/Vec/Point/Rect/FileStorage(YAML 子集)/平面 PnP/Rodrigues/projectPoints/
pointPolygonTest`，不入库）编译了**全部不依赖图像处理的代码**：

| `config` `pose` `pose_buffer` `tracker` `target` `ballistics` `aimer` `serial_protocol` `evaluation` `io/serial_port` `roi` | `detector`（imgproc/dnn）、`draw`、各 app 的视频读写 |
| `autoaim_tests`、`sentry_tests`（除检测器退化输入用例）、`serial_port_tests`（PTY 端到端） | 3.avi / 4.avi 实拍回归（视频不在仓库里） |
| `autoaim_sim` 仿真器（8 个场景，加印了哨兵策略列） | `tools/regression.py` 门禁 |

改动过的 app（`sentry_robot`、`sentry_offline`、`sentry.cpp`）另用声明桩做了
`-fsyntax-only` 编译检查。仿真里的 PnP 是兼容层实现（单应初始化 + 镜像解 + LM），
与 IPPE 在噪声水平上一致、不逐位相同，所以**只做同一二进制下的 A/B**，不与 README
的绝对数字比较（README 自己也说明仿真跨平台会漂 3 pp）。

原始代码在该环境下 3 个测试程序全部通过，仿真结果与 README 趋势一致——核心可复刻。

## 3. 缺陷清单（已全部修复，均有回归测试）

| # | 严重度 | 位置 | 问题 | 影响 |
|---|---|---|---|---|
| 1 | 高 | `io/serial_port.cpp` | tty 不是 raw 模式：保留了驱动默认 `ICRNL`，**每个 0x0D 字节读成 0x0A** | 任一字节恰为 0x0D 的帧被改写，误差随字节位置从 3e-4° 到约 20°（如 yaw 原始值 0x00010D0D=6.8877° 读成 6.8106°）。PTY 实测复现 |
| 2 | 高 | `io/serial_port.cpp` | `fd_` 被读线程与 `send()` 同时 close/reopen，无同步 | 双重 close 可能关掉已被系统复用的描述符（如相机）；数据竞争 |
| 3 | 高 | `io/serial_port.cpp` | 非阻塞写遇 `EAGAIN`、读遇 `EAGAIN/EINTR` 都当作断线重连 | 发送队列短暂满就断开重连 |
| 4 | 高 | `apps/sentry_robot.cpp` + `PoseBuffer` | 默认 `--exposure-offset-ms 0` 时帧戳总比最新姿态样本新，严格包围查询**每帧失败** | 默认参数上车：所有帧被跳过 |
| 5 | 高 | `target.cpp` | 观测先过空间门限，失败就为同一身份**再建一条轨迹** | 同 id 重复轨迹，选择/火控滞回在两者间翻转；原轨迹看不到远处观测，跟踪器自带的发散保护失效 |
| 6 | 中 | `target.cpp::select` | 切换滞回在全部状态里按 id 找上一目标 | 已掉到 TEMP_LOST（`require_tracking`）或超出 `max_distance` 的目标被"留住" |
| 7 | 中 | `aimer.cpp` | 中心模式用 t0 时刻的中心，不计弹丸飞行期间的平移 | 平移小陀螺下误差 v·t_fly（1 m/s 时约 25 cm） |
| 8 | 中 | `types.hpp::wrapAngle` | `while` 循环，对 ±inf 永不返回，大值 O(\|a\|) | 滤波器发散成 inf 时视觉进程挂死（实测 timeout） |
| 9 | 低 | `tracker.cpp::predict` | Singer 模型外推位置但不衰减速度 | `TargetState(t1).centerAt(t2) ≠ TargetState(t2).center`，快照在非滤波时刻取时过冲 |
| 10 | 低 | `tracker.cpp::armorAt` | 板高度不随中心的竖直外推变化 | 与 `centerAt` 不一致 |
| 11 | 低 | `sentry.cpp` ROI | 前哨站窗口用了普通装甲的俯仰；"身后"判断用世界 x 而非相机深度 | 窗口偏差；云台转动后判断错误 |
| 12 | 低 | `sentry_robot.cpp` | 前馈 yaw_vel 跨目标切换/跳帧做差分 | 切换那一帧速度饱和到 `gimbal_max_rate` |
| 13 | 低 | `sentry.hpp` | `SentryVision` 成员互相持有引用却可拷贝 | 拷贝后悬空引用 |

## 4. 优化策略与实施

策略：**先修正确性，再做可测量的性能优化，最后做工程化**；每项改动都配一个在旧代码上会失败的测试
（已验证：新增用例在原代码上 36 处失败，`wrapAngle(inf)` 原代码超时）。

1. **串口链路**（#1–#3）：读线程独占描述符的打开/关闭/重连，`send()` 在同一互斥锁下写，
   出错只"请求重连"；`EAGAIN` 时 poll 等待；`POLLHUP/POLLERR` 才视为断线；termios 改为
   cfmakeraw 等价；同一次 read 中的多帧按其后到达字节数回推线缆时间（8N1 每字节 10 bit），
   新增 `reconnects()` 计数。
2. **姿态外推**（#4）：`PoseBuffer(capacity, max_gap, max_extrapolation)`，超出最新样本
   `max_extrapolation` 以内用最后两样本 SLERP(t>1) 外推；默认 0（原语义），
   `sentry_robot --max-extrap-ms` 默认 10。
3. **一身份一轨迹**（#5）：`deviceId`（颜色+编号+尺寸）唯一对应一台车、前哨站唯一，
   所以同 key 的全部观测直接交给该 key 的跟踪器，由跟踪器自己的马氏门限拒绝误识别、
   由发散保护在目标真的换位置时重新初始化。管理器的关联代码从约 130 行降到约 70 行；
   `target.association_gate` 不再使用（保留以兼容旧 YAML）。
4. **选择滞回只保留合格目标**（#6）。
5. **中心模式提前量**（#7）：迭代内用 `centerAt(t0 + t_fly)`。
6. **数值健壮性**（#8–#10）：`wrapAngle` 改为 `std::remainder`，O(1)，非有限值原样返回；
   Singer 外推同步衰减速度；板高度随中心竖直外推。
7. **弹道 10 倍提速**：RK4 步长 1 ms → 10 ms，命中横距处由线性插值改为三次 Hermite
   （用两端精确导数）；对 1–25 m、俯仰 −17°…34° 网格，相对 10 µs 参考解的高度误差
   < 0.05 µm（原实现 1.2 µm）。俯仰求解由不动点迭代改为割线法（首步仍为不动点，
   斜率异常时回退），同样的 0.5 mm 收敛判据。
8. **ROI 窗口合并**：同一辆车 4 个槽位的窗口高度重叠，先合并成外接矩形
   （`sentry::mergeWindows`，独立的 `src/roi.cpp`），减少重复的掩膜/形态学/轮廓计算，
   并消除窗口内部边界把灯条截成两段、回灌重复灯条的问题。`sentry_offline` 新增 `--roi`。
9. **配置**：`Config::validate()` 在加载时检查会在深处变成 NaN/除零/错误几何的参数
   （如 `bullet_speed`、`gimbal_tau`、`armors_num`、外参旋转是否正交且 det=+1），
   一次性列出全部问题；补齐 `aimer.yaw_offset_deg / pitch_offset_deg`（在最终指令上施加，
   不影响选板与开火判定），`--set yaw_offset=… pitch_offset=…` 可扫。
10. **解耦**：`serial_protocol.hpp` 不再包含 `sentry.hpp`（原来串口协议间接依赖 OpenCV/
    检测器）；`SerialCommand` 移入协议头。该文件现在可不带 OpenCV 单独编译（已验证）。

### 性能（单线程，同机）

| | 原 | 现 |
|---|---|---|
| `RobotAimer::aim` | 259 µs/次 | **28 µs/次** |
| `Ballistics::solve` | 87 µs/次 | **8.6 µs/次** |

## 6. 合并前必须补做（本环境做不到）

1. `python3 tools/regression.py`（3.avi / 4.avi + 仿真门禁）。弹道数值变化在 µm 级，
   预期整车 EKF 数字不变；哨兵策略因 #5/#6 可能有小幅变化，应与 README 的
   68.0% / 10.3 与 68.5% / 9.6 对照。
2. `sentry_offline <video> --roi` 与不带 `--roi` 对照（窗口合并后的漏检与命中率）。
3. 实车：`sentry_robot` 结束时打印的 `attitude misses` 在默认参数下应接近 0；
   `reconnects` 在稳态应为 0；拔插 USB 验证重连。
4. 若下位机发送频率很低（<100 Hz），按实测把 `--max-extrap-ms` 调小或设 0。

## 7. 建议的后续优化（未实施）

- 自适应 Q 在实拍中从不触发（README 已测得 NIS≈3）：触发量改为 `NIS − 3` 的超出量
  或 χ² 分位数；需实拍扫参。
- `RobotTracker` 与 `OutpostTracker` 的关联/更新/状态机代码几乎重复，可抽成模板基类。
- 数字分类器逐板 `forward`，可用 `blobFromImages` 批量一次前向。
- 控制帧没有 CRC（无空闲字节）——协议 v2 时加长度字段与 CRC-16。
- 前哨站改为固定几何的 5 维模型（见 `SENTRY_BACKLOG.md` P1-5）。

# 重捕后的开火门（warmup_frames）

## 背景

D-01 的分层显示：**重捕后 ≤3 帧的射击命中率 62.2%，稳态 68.1%**，而这段占全部射击的 18.4%。
既然刚恢复的那几帧本来就不准，一个自然的想法是“先别开火，等估计稳了再说”。

## 实现

`aimer.warmup_frames`（默认 0 = 关闭）：跟踪器新增 `trackingFrames()`，记录本次进入
TRACKING 后连续跟踪的帧数；开火条件加一条 `trackingFrames() >= warmup_frames`。

## 实测

| warmup | 3.avi 命中率 | 3.avi hits/s | 4.avi 命中率 | 4.avi hits/s | DPS（3/4） |
|---|---|---|---|---|---|
| **0（默认）** | 67.6% | **10.6** | 68.6% | **10.0** | **716 / 686** |
| 3 | 68.2% | 10.0 | 67.9% | 9.0 | 682 / 611 |
| 5 | 69.1% | 9.5 | 68.9% | 7.8 | 656 / 537 |
| 8 | 69.8% | 8.5 | 68.8% | 6.5 | 593 / 447 |
| 12 | 70.5% | 7.3 | 69.4% | 5.1 | 515 / 354 |

## 结论

- 命中率单调升（67.6 → 70.5），射频单调降（10.6 → 7.3），**DPS 单调降**。
- 这说明 D-01 的机制是真的（重捕后确实更差），但**靠“少开火”去规避它是负收益**——
  和开火窗口那次的结论一模一样。
- 默认保持 **0（关闭）**，参数留着供特殊场景（例如远距离狙击模式）使用。
- 真正该做的是**把重捕后的估计做好**，而不是把这段射击掐掉：
  思路是 LOST 期间保留旧轨迹并用预测位置续命（放大协方差），重见时做速度一致性校验，
  让 `tracking_thres` 之后的第一帧就已经是准的。

*数据为两视频虚拟射击；DPS = 命中率 × 射频。*

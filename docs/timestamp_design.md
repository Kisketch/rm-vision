# 时间戳与延迟预算（G-02）

目标：把 R-04（曝光时间戳）和 R-05（端到端延迟）的验收标准，从“拍脑袋”变成可推导的数。

## 已知常数

- 帧率 25 fps → 帧间隔 **40 ms**
- 当前假设延迟 **60 ms**（capture → 子弹出膛）
- 弹速 25 m/s，6 m 处飞行 **240 ms**
- 装甲板半宽 67.5 mm，6 m 处张角 **0.64°**

## 误差换算

- 目标以 3 rad/s（172°/s）旋转时，**1 ms 的时间误差 = 0.172°** 的角度误差。
- 我们允许时间误差吃掉板半宽的 20%，即 0.13° → 允许时间误差 **0.75 ms**。

## 由此得到的验收线

| 项 | 允许误差 | 依据 |
| --- | --- | --- |
| 曝光时间戳抖动 σ | ≤ 0.3 ms | 占预算 40%（均方根分配） |
| 图像→姿态对齐误差 | ≤ 0.3 ms | 姿态环形缓冲插值残差 |
| 总延迟估计误差 | ≤ 0.4 ms | 等效 0.08° |
| **三者均方根合计** | ≤ 0.75 ms | 与总预算一致（RSS 合成，不线性相加） |
| 延迟绝对值 | 实测替换 60 ms | 误差在 60±15 ms 内对命中率影响 <1 pp（仿真扫描） |

## 采样与延迟的关系（为什么提帧率有用但不翻倍）

- 25 fps 时，一帧内目标转过 6.9°，检测本身就有 ±20 ms 的量化误差。
- 100 fps 时降到 ±5 ms，量化误差减少 15 ms。
- 但飞行时间 240 ms 不变，预测仍然要外推同样久；所以帧率收益来自**估计方差**与**检测延迟**，不是外推长度。

## 落地步骤（对应 R-04 / R-05）

1. 相机侧：`MV-CS016-10UC` 开硬件触发或取 `ExposureStartTime`，与主机时钟做 PTP/chrony 对齐，记录每次曝光的绝对时间戳。
2. 姿态侧：串口每帧带 IMU 四元数 + 时间戳，按曝光时间戳做**环形缓冲插值**（不是取最新值）。
3. 链路侧：用高速相机拍“屏幕闪光 → 云台动作”，或让 MCU 回传接收时刻，实测四段延迟之和。
4. 验收：把实测值写回 `aimer.latency`，跑 `tools/regression.py`，命中率不得回退。

# 畸变系数顺序：影响有多大（A-02）

旧仓 `text.yaml` 的 `distort_coeffs` 第三项是 `0.29333`。按 OpenCV 约定
`(k1,k2,p1,p2,k3)` 它是切向系数 p1，比正常值大两个数量级；按 `(k1,k2,k3,p1,p2)`
读则是 k3，合理。**没有原始标定图就无法判定哪个是真**，但可以量化代价。

## 重投影误差（24 个合成视角，9×6 棋盘，25 mm 方格）

- 两种读法之间的 RMS 差：中位 **46.70 px**，最大 **237.89 px**
- 棋盘占画面约 1/3，若整幅都是棋盘，差异会再放大约 1.7×

## 瞄准点偏移（6 m 处，光轴外不同角度）

| 离轴角 | 两种顺序的投影差 |
| --- | --- |
| 0° | 0.00 px |
| 10° | 21.86 px |
| 25° | 152.94 px |
| 35° | 349.64 px |

6 m 处一块装甲板半宽 ≈ 24 px（1440 宽、fx≈2400）。

## 结论

- 中心视场几乎无差别（0.00 px），**边缘才明显**：25° 处 152.94 px，35° 处 349.64 px。
- 这说明如果次序有误，离轴投影偏差可能很大；合成实验本身不能证明实际偏差的原因，也不能确定哪一种次序正确。
- **判定方法**：拿到原始标定图后，用两种顺序各算一次重投影 RMS，取小者；
  或在标定板上取一个边缘角点，比较实测与两种预测的像素差（>3 px 即可判定）。
- 2026-11-10 核对：当前 `core/config/default.yaml` 实际使用旧 `text.yaml` 导入的非零系数；零畸变只在显式的 `core/config/video_reference.yaml` 离线参考配置中使用。旧文档将零畸变称为“当前默认”已过时。
- 源码链路：`legacy/text.yaml` → `legacy/Armor/src/ArmorSolver.cpp:26–31` 原样转成 OpenCV 矩阵 → `solvePnP`。这只能证明旧程序如何使用这些系数，不能证明原始标定输出的顺序。仓库中的 `tools/calibrate_camera.py` 和 `tools/calibrate_intrinsics.py` 是现有标定工具，尚无证据表明它们产生了旧系数。
